Scope delivered (all criteria map to code under streamlit/ + tests + docs)
--------------------------------------------------------------------------
* streamlit/sections/analysis.py  — full Card-2 analysis page, four sections,
  all numbers read from dbt relations:
    - Attribution overview: valid conversions, commission, matched /
      unmatched / ambiguous, match rate and unmatched rate over the
      revenue-valid population (marts.fct_revenue_attribution, 92 rows).
      Reconciliation strip: decided conversions (100) = valid 92 + denied 8.
      The decided total is read from marts.mart_attribution_health
      (sum(total_conversions)), NOT from intermediate.int_conversion_
      attribution, so the page's only intermediate read is the ADR-8
      diagnostic view. Detailed mart rows (fct_revenue_attribution and
      mart_attribution_health) live in a collapsible audit expander.
    - Why conversions are not attributed: bar chart + table over
      intermediate.int_unmatched_conversions grouped by unmatched_reason.
      The five-reason dbt taxonomy is zero-filled (missing_click_id,
      click_id_not_found, outside_posthog_sample_window,
      multiple_candidates, unknown). Percentages are guarded against an
      empty relation: when the total is 0 the rendered percents are 0.0
      (never NaN from a 0/0 division), so an all-matched warehouse still
      renders a complete count-and-percentage diagnosis.
    - Marketing attribution: conversions AND commission by utm_source shown
      as two side-by-side horizontal bar charts (the visual requirement),
      plus an audit table carrying both columns; only attributed sessions
      are grouped, and unmatched/ambiguous conversions roll into an explicit
      'Unattributed' bucket (no channel inferred). Match-method panel shows
      the gclid_exact / fbclid_exact / url_click_exact vocabulary zero-filled
      with an empty-state note when no method was exercised.
    - Revenue and commission: attributed vs unattributed commission over the
      valid population; fct_commission_daily_local is shown strictly as a
      labelled daily proxy (line chart + audit table) complement, never as
      the authoritative source.
* No attribution rule, eligibility window, business join, or taxonomy is
  re-implemented in Python. Every value is an aggregate over a dbt relation.
  The only non-mart read is intermediate.int_unmatched_conversions, consumed
  for its pre-computed unmatched_reason column only (ADR #8).

Rework round 1 (reviewer changes requested) — how each item was addressed
--------------------------------------------------------------------------
1. Empty-population NaN: `_unmatched_reason_counts` now computes the total
   from the counts list and assigns 0.0 percent when the total is 0. New
   hermetic test `test_unmatched_reason_counts_empty_relation_returns_zero_
   percentages` deletes the diagnostic rows and asserts complete taxonomy +
   all valid 0.0% (no NaN).
2. Commission-by-source bar: marketing attribution now renders TWO side-by-
   side horizontal bar charts — conversions by source (#1f77b4) and
   commission by source (#ff7f0e) — above the audit table. New AppTest
   `test_analysis_page_shows_both_source_bars` inspects the rendered
   Vega-Lite specs and asserts exactly two source bars whose x-fields are
   {"conversions", "commission_gbp"}.
3. Intermediate access beyond ADR 8: the decided/denied audit totals are now
   derived from marts.mart_attribution_health (sum of total_conversions)
   instead of intermediate.int_conversion_attribution. The guard test now
   asserts `intermediate.int_conversion_attribution` is NOT read; ADR 8 and
   the README were updated to state the only intermediate read is the
   diagnostic unmatched view.
