Investigation / root cause (deviates from the card's stated premise)
--------------------------------------------------------------------
* The card says "O projeto usa Poetry para dependências". That premise does
  NOT match this repository: there is no Poetry anywhere in git history.
  - pyproject.toml is a plain PEP 621/setuptools manifest ([project] +
    [build-system] setuptools), with optional-dependencies extras; there is
    no [tool.poetry] section on main or on any branch/dangling object.
  - There is no poetry.lock, Pipfile, or requirements.txt in any revision.
  - Local install/run path is `pip install -e ".[consumer,dev]"` and
    `streamlit run streamlit/app.py` (README).
* Streamlit Community Cloud treats a root pyproject.toml as a POETRY manifest
  and runs `poetry install`. Because this project is not an installable
  package, Poetry fails with the exact observed error:
      The current project could not be installed: No file/folder found for
      package pfm-assignment
  So the error is real; the "Poetry project" framing is the platform's
  default reading of the root pyproject.toml, not an actual Poetry setup.
* Streamlit's official dependency docs (docs.streamlit.io, fetched 2026-09-04)
  confirm the platform's resolution order in each location:
      uv.lock (uv) -> Pipfile (pipenv) -> environment.yml (conda) ->
      requirements.txt (pip) -> pyproject.toml (poetry)
  and that "you should only use one dependency file for your app". A root
  requirements.txt therefore makes the deploy install with pip/uv and never
  invoke Poetry, while pyproject.toml remains for local development.

Python runtime pinning (Community Cloud)
----------------------------------------
* Community Cloud default Python is 3.12 (per official docs) and lets the
  owner choose a version in Advanced settings; no repo file selects it.
* Python 3.14 is NOT used: pip dry-run on Python 3.14 showed pandas 2.2.3 has
  no cp314 wheel and tries to compile from source (fails). The validated pins
  all ship cp312 wheels (pandas 2.2.3 cp312 verified on PyPI), so 3.12 is the
  supported, conflict-free runtime.
