What changed
------------
1. Overview page (streamlit/sections/overview.py)
   - New subheader "The reported production problem": the 18% figure is cited
     verbatim as an assignment premise ("18% of TrackNow conversions in the
     last 30 days have no matching PostHog session") and explicitly never
     re-derived from the sample.
   - New subheader "What this executable sample demonstrates": the sample is
     an anonymised, bounded extract (100 TrackNow conversions / 200 PostHog
           sessions); the provided anonymised sample does not contain a deterministic
           cross-system identity overlap, so the local exact-match model attributes
           none of it — a property of the file, not a production measurement.
   - Visual callout (st.info):
       Reported production gap: 18%
       Observed deterministic match rate in provided anonymised sample: 0%
       These numbers describe different populations and should not be
       compared as if one validates the other.
     The sample-side rate is READ LIVE from marts.mart_attribution_health
     (decided/matched sums) on every render, so it cannot drift from the
     warehouse; only the 18% side is a fixed premise.
   - require_connection() moved earlier so the callout has the warehouse.

2. Analysis page (streamlit/sections/analysis.py)
   - Diagnosis section renamed: "Why conversions are not attributed" ->
     "What the provided sample can diagnose".
   - Removed universal-claim narrative: "the honest result, not a missing
     step" and "not places where a better join would help" are gone.
   - New sample-scoped framing: the taxonomy diagnoses the anonymised
     extract; production would additionally expose identity-bridge,
     propagation and collection gaps the file cannot show (pointer to the
     Methodology investigation plan). The taxonomy itself is unchanged:
     missing_click_id / click_id_not_found / outside_posthog_sample_window /
     multiple_candidates / unknown.

3. Methodology page (streamlit/sections/methodology.py) — four sections:
   1. "Production attribution design" — the end-to-end identity flow
      (ad click -> gclid/fbclid -> PostHog session + distinct_id ->
      persistence/identity bridge -> affiliate outbound click ->
      TrackNow click_id / affiliate_session_id -> conversion) rendered as a
      code block, plus the role of every identifier: gclid/fbclid,
      click_id_from_url, distinct_id, session_id, click_id,
      affiliate_session_id. Two design constraints stated explicitly:
      identifiers persisted with the session and propagated onto the
      affiliate redirect; affiliate_session_id treated as part of the
      TrackNow contract (a key to attribution) WITHOUT assuming it equals
      PostHog.session_id.
   2. "Sample implementation" — the four deterministic rules unchanged, but
      framed as the sample implementation constraint, not the production
      architecture. Rule 1 now says the absence of a documented contract is
      a data limitation, NOT evidence that affiliate_session_id is
      irrelevant.
   3. NEW "How I would investigate the reported 18% attribution gap" — six
      pseudo-BigQuery diagnostic queries (daily baseline; identifier
      coverage incl. missing click_id/affiliate_session_id and
      gclid/fbclid presence; gap by channel Google/Meta/other; gap by
      device/browser/country incl. Safari/iOS and consent surfaces;
      conversion lag between first paid session / affiliate click /
      conversion; TrackNow propagation audit comparing outbound-click
      values with conversion values) and six hypotheses, each with Test and
      Fix: identifier lost before TrackNow; cross-session conversion;
      cross-device/cookie reset/incognito; redirect stripping/affiliate
      integration; consent/ad blocker/collection gap; ingestion
      latency/freshness. Closes with the root-cause boundary statement:
      the exact production root cause cannot be proven from the delivered
      sample; the fix depends on which test wins.
   4. "Limitations" and "Recommendations" — unchanged structure; the
      "No fuzzy rules or undocumented bridges" limitation now says the
      constraint is sample-deliberate and the production contract is in the
      design section.

4. dbt documentation (no SQL logic changed; join still exact only)
   - docs/decisions.md: ADR 3 rewritten — exact click-id matching is what
     the SAMPLE can prove; production needs an explicit identity contract
     (capture, persistence, propagation, TrackNow contract including
     affiliate_session_id); the sample does not prove affiliate_session_id
     irrelevant. NEW ADR 11: the reported production gap (18%) and the
     sample's match rate (0%) are different populations; never compared as
     if one validates the other; no fuzzy bridge is added.
   - int_conversion_attribution.sql header: now opens with "SAMPLE
     IMPLEMENTATION CONSTRAINT, NOT THE PRODUCTION ARCHITECTURE... because
     no documented cross-system bridge is available in the delivered data".
   - schema.yml: int_conversion_attribution description carries the
     sample-constraint framing; all four affiliate_session_id column
     descriptions now scope the "not a join key" statement to the sample
     and name it part of the production TrackNow identity contract.
   - winner_rules.yml: unit-test description marked as sample-scope checks.

5. README.md — walkthrough description updated to the new page structure
   (two populations on Overview; four-part Methodology incl. investigation).
