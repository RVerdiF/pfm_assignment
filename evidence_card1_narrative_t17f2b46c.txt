What changed (final)
--------------------
1. Overview page (streamlit/sections/overview.py)
   - New subheader "The reported production problem": the 18% figure is cited
     verbatim as an assignment premise ("18% of TrackNow conversions in the
     last 30 days have no matching PostHog session") and explicitly never
     re-derived from the sample.
   - New subheader "What this executable sample demonstrates": the sample is
     an anonymised, bounded extract (100 TrackNow conversions / 200 PostHog
     sessions); the provided anonymised sample does not contain deterministic
     cross-system identifier overlap, so the local exact-match model attributes
     none of it - a factual property of the file, not a production measurement.
   - Visual callout (st.info):
       Reported production gap: 18%
       Observed deterministic match rate in provided anonymised sample: 0%
       These numbers describe different populations and should not be
       compared as if one validates the other.
   - The sample-side rate is READ LIVE from marts.mart_attribution_health
     (decided/matched sums) on every render.

2. Analysis page (streamlit/sections/analysis.py)
   - Diagnosis section renamed: "Why conversions are not attributed" ->
     "What the provided sample can diagnose".
   - Removed universal-claim narrative.
   - New sample-scoped framing: the taxonomy diagnoses the anonymised
     extract; production would additionally expose identity-bridge,
     propagation and collection gaps the file cannot show.

3. Methodology page (streamlit/sections/methodology.py) - four sections:
   1. "Production attribution design" - end-to-end identity flow
      (gclid/fbclid → PostHog distinct_id/session → attribution bridge →
      TrackNow click_id → conversion resolves bridge) plus utm_content as
      Meta ad/creative enrichment.
   2. "Sample implementation" - four deterministic rules framed as sample
      constraint.
   3. "Edge cases and data-model handling" - 5 explicit cases: missing
      click_id, cross-session, multiple paid clicks, cookie reset/cross-device,
      late-arriving data.
   4. "How I would investigate the reported 18% attribution gap" - six
      pseudo-BigQuery diagnostic queries (using documented production contract:
      TrackNow conversions, attribution.bridge, PostHog sessions):
      - Query 1: TrackNow LEFT JOIN bridge LEFT JOIN PostHog; unmatched = ph.session_id IS NULL.
      - Query 2: identifier coverage (click_id, affiliate_session_id, bridge record).
      - Query 3: gap by acquired channel (google/meta/other).
      - Query 4: gap by TrackNow documented fields (firm_id, trading_platform, first_order).
      - Query 5: conversion lag between session and conversion.
      - Query 6: propagation audit via stable click key (event_id) between
        tracknow.conversions and tracknow.outbound_clicks.
      Six hypotheses, each with Test and Fix. Root-cause boundary: "The
      provided anonymised sample does not contain a deterministic cross-system
      identity overlap."
   5. "Limitations" and "Recommendations" - unchanged structure.

4. dbt documentation (no SQL logic changed; join still exact only)
   - ADR 3 rewritten: exact click-id matching is the sample constraint;
     production needs explicit identity contract.
   - ADR 11: reported gap (18%) and sample match rate (0%) are different
     populations.
   - Model headers reframed accordingly.

5. Tests (tests/test_narrative_alignment.py, test_methodology_page.py)
   - test_investigation_query_4_uses_tracknow_documented_fields: asserts
     firm_id/trading_platform/first_order, no invented telemetry.

   - All query titles and hypothesis references synced.
